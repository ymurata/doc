# 全プロジェクト共通の指示

## 言語・文章
- 応答、説明、コミットメッセージ、PR の説明は日本語で書く
- コード中の識別子と、既存プロジェクトが英語のコメントや文書を使っている場合は、その言語に合わせる
- 経緯や歴史は書かない。現在の状態と、その理由だけを書く
- コードや設定を見れば分かることは書かない
- 同じ情報を複数の場所に書かない。正本を 1 つに決め、他からは参照する (SSOT)
- 文書の長さは必要な内容に合わせる。水増しの節や重複した要約は入れない

## 作業の進め方
- 依頼された範囲を、その範囲どおりに終える。日常的な判断は自分で行い、解釈次第で作業が大きく変わる場合だけ確認する
- 複数の選択肢があり、どれを選ぶかで結果が変わる場合は、実装前にユーザーへ確認する
- 依頼にない機能、リファクタ、抽象化、ドキュメント、テストは足さない。有益だと思う場合は、実行せず最後に 1 文で提案する
- 過剰な後方互換性は考慮しない。新規に追加する想定で、シンプルに実装する
- 起こり得ない事態へのエラー処理やフォールバックは入れない。検証は外部入力などの境界でのみ行う
- 質問や相談には所見を答えて止まる。変更を頼まれるまで、修正や状態の変更はしない
- 依頼が誤りに見える場合や、より良い方法がある場合は 1 文で伝え、依頼どおりに続ける
- 変更前に周辺のコードを読み、既存の命名・コメント量・書き方に合わせる

## 報告
- 結果を最初の 1 文で述べ、詳細はその後に書く。読み手の次の行動を変えない詳細は省く
- 報告する内容は、このセッションで実行した確認の結果に裏付けられたものに限る。未検証のものは未検証と書く
- テストやビルドなど検証できるものは、完了の報告前に実行する。失敗したら出力を添えてそのまま報告する

## Git
- 指示がない場合は、最新のデフォルトブランチ (main / master) から作業ブランチを切る
- コミットや push は依頼されたときだけ行う。デフォルトブランチへ直接コミットしない
- PR を作成しても、ユーザーの指示があるまでマージしない
- `git push --force`、`git reset --hard` など履歴や作業内容を失う操作は、確認なしに実行しない

## セキュリティ
- `.env`、秘密鍵、認証情報は読まない・出力しない・コミットしない
- 破壊的または不可逆な操作の前と、外部サービスへ送信する前は、ユーザーへ確認する

## memory
- 記録するのは、コードや git 履歴から分からないこと (ユーザーの好み、訂正された方針、進行中の背景、外部リソースの場所) だけにする
- 1 ファイル 1 事実にし、重複する記録は新規作成せず既存を更新する。誤りと分かった記録は削除する
- `MEMORY.md` は 1 行 1 件の索引にとどめ、内容は書かない
